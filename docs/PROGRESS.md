# Журнал разработки «После героя»

Накопительный журнал прогресса. Одна запись на микроэтап: что сделано,
как проверить. Пополняется в том же коммите, что и микроэтап.

## M0 — подготовка

### M0.1 — инициализация проекта

- Установлен Go 1.27.1 (`brew install go`).
- Инициализирован git-репозиторий и модуль `afterhero`.
- `.gitignore` для бинарников и артефактов Go.

Проверка: `go version` → go1.27.1 darwin/arm64.

### M0.2 — спецификация и процесс

- `DESIGN.md` — финальная спецификация MVP с тремя поправками,
  принятыми при ревью: `turn++` — последняя операция `Step`; страх — чистая
  производная от памяти без хранимого поля; выбор тела кодируется событием
  `BodyChosen` (не расходует ход, но воспроизводится в replay).
- `docs/PROGRESS.md` — этот журнал.
- Процесс: микроэтап → зелёные `go test ./...` и `go vet ./...` → запись сюда →
  осмысленный коммит.

## M1 — чистое ядро симуляции

### M1.1 — идентификаторы и стабильные enum'ы

- `internal/sim/id.go` — `EntityID`, `ItemID`, `Seq` (все с 1, ноль = «участника нет»,
  переиспользование ID запрещено), `Vec2` с `Add` и `Manhattan`.
- `internal/sim/enums.go` — все сериализуемые enum'ы с явными стабильными
  значениями: клетки, виды существ (= фракции в MVP), действия, события (15 видов),
  предметы, причины смерти/урона, состояния целей мести, исходы кампании.
  Схема событий: `SchemaVersion = 1`.
- `internal/sim/enums_test.go` — `TestEnumStability` фиксирует каждое числовое
  значение (переупорядочивание констант = громкий провал, а не тихая порча replay);
  `TestVec2` — арифметика координат.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.2 — события и действия

- `internal/sim/event.go` — плоская структура `Event` (один struct на все виды
  фактов: фиксированный порядок полей сериализации бесплатно, лёгкий байт-в-байт
  диф); `Cause` полисемантично по Kind; `EventKind.Memorable()` — договор отбора
  фактов в память: бытовые факты не топят кольцо, метафакты игрока (переселение,
  цели мести) обитателям недоступны.
- `internal/sim/action.go` — `Action` как намерение + конструкторы
  (Move/Wait/Attack/PickUp/Drop/Use) + `Validate()` — синтаксическая валидация
  без мира; `ErrInvalidAction` (без событий, без расхода хода).
- `internal/sim/event_test.go` — round-trip JSON, порядок полей, omitempty,
  таблица Memorable, таблица валидации действий.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.3 — сценарий: ручная карта 32×20

- `internal/sim/scenario.go` — `defaultMap`: ручная карта с тремя зонами
  (кладовая гоблинов, большой зал, святилище культистов, крысиные тоннели),
  12 существ (4×гоблин, 4×крыса, 4×культис), 6 еды и 2 оружия; строгий
  `ParseMap` (прямоугольность, известные символы, порядок чтения = будущий
  порядок ID); `Cell` вне карты = стена, `Walkable`.
- `internal/sim/scenario_test.go` — размеры, состав населения и предметов,
  уникальность позиций, замкнутость границ, BFS-связность от игрока до
  каждого существа и предмета (герметичная зона = тише гроба), ошибки парсера.

Дизайн-решение: `Scenario` не содержит ID и состояния — их назначает
`NewWorld` в M1.4, так genesis-событие остаётся полным описанием партии.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.4 — существа, предметы, genesis

- `internal/sim/creature.go` — `Creature` (HP, инвентарь, память-кольцо
  на 32 события с `remember`), характеристики видов через switch-таблицы
  `KindMaxHP`/`KindDamage` (гоблин 6/2, крыса 4/1, культис 5/2).
- `internal/sim/item.go` — `Item` с инвариантом места (Holder=0 → на земле
  в Pos, иначе в инвентаре), трупы — предметы с Owner.
- `internal/sim/world.go` — `World` (map только для поиска, стабильный
  `order` для очереди NPC), `Genesis`-payload; `NewWorld` строит мир
  **через применение собственного genesis-события** — начало партии
  и replay не могут разойтись по построению; `emit` — единственная дверь
  к изменению мира.
- `internal/sim/apply.go` — reducer `applyEvent` (пока только WorldCreated)
  + `applyGenesis`; счётчик событий восстанавливается из потока.
- `internal/sim/world_test.go` — содержимое genesis (12 существ, 8 предметов,
  ID в порядке чтения карты, игрок-гоблин #1), соответствие мира событию,
  JSON round-trip.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.5 — канонический JSONL

- `internal/sim/serialize.go` — `EncodeEvents` (json.Encoder с
  `SetEscapeHTML(false)`, одна строка = одно событие), `ReadEvents`
  (номер строки в ошибках, пустые строки запрещены; пустой поток = ноль
  событий без ошибки — валидность «первое событие — genesis» осталась
  за replay), `Event.canonicalize()` — сортировка свидетелей в emit,
  событие рождается каноническим.
- `internal/sim/serialize_test.go` — байт-в-байт повторное кодирование,
  стабильность байтов через round-trip, строка-на-событие, контракт
  чтения, канонизация свидетелей.

Найден и исправлен подводный камень теста: `bytes.Buffer.Bytes()` возвращает
только непрочитанный остаток — после `ReadEvents` буфер «пуст». Снимок байтов
для сравнения теперь делается до чтения.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.6 — replay и канонический слепок

- `internal/sim/replay.go` — `WorldFromEvents`: восстановление мира только
  через `applyEvent`, без AI/RNG/сценария; проверки до применения (пустой
  поток, не genesis первым, чужая версия схемы, дыры в нумерации seq).
- `internal/sim/snapshot.go` — `Snapshot`/`World.Snapshot()`: канонический
  слепок состояния для сравнения миров и read-only рендера; срезы инвентаря
  и памяти копируются насквозь (слепок не алиасит живой мир); терраин
  не входит — в MVP он неизменен.
- `internal/sim/replay_test.go` — replay == живой мир по слепку, JSON
  round-trip слепка, отказ от битых потоков.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.7 — конвейер хода Step

- `internal/sim/step.go` — `Step(playerAction) ([]Event, error)`: шесть фаз
  (игрок → NPC по снимку order → upkeep → закрытие целей → end-проверки →
  TurnEnded); фазы 3–5 — каркасы под M3/M5. `act` — единая семантическая
  проверка+применение для игрока и NPC с инвариантом «ошибка без событий /
  события без ошибки»; откат `turn--` при невалидном шаге (ход не расходуется);
  `occupiedBy` — живые существа занимают клетку, предметы на полу — нет.
- `apply.go` — Moved (позиция из события), Waited (факт без изменений),
  TurnEnded (`w.turn = e.Turn`).
- Модель нумерации ходов (поправка к DESIGN §4): номер растёт в начале `Step`,
  все события хода несут один номер, replay восстанавливает счётчик
  из `TurnEnded`.
- `internal/sim/step_test.go` — ожидание и шаг, стена и занятая клетка
  (ошибка без расхода хода), неподдержанные действия, replay партии
  из пяти ходов.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.8 — детерминизм и headless

- `internal/sim/determinism_test.go` — байт-в-байт прогоны одинаковой партии;
  инвариант к порядку обхода Go-map (25 свежих прогонов: порядок map случаен
  почти при каждом обходе — случайная итерация поймается почти наверняка);
  разные seed дают разные потоки.
- `cmd/headless` — партия без движка: JSONL в stdout, сводка в stderr;
  детерминированный «водитель» игрока на отдельном генераторе (не rng мира),
  недопустимые шаги пережидаются. Доказывает сборкой, что sim не зависит
  от Ebitengine.
- Smoke: два прогона `-seed 7 -turns 120` идентичны (`cmp`), 241 событие,
  12 живых; строки JSONL читаются глазами.

Проверка: `go test ./...` и `go vet ./...` — зелёные; `go run ./cmd/headless`
два раза → `cmp` пуст.

**Веха M1 закрыта: чистое ядро готово** — genesis, события, действия,
карта, конвейер хода, сериализация, replay и детерминизм.

## M2 — окно, рендер и ввод

### M2.1 — окно Ebitengine

- `go get github.com/hajimehoshi/ebiten/v2 v2.9.10` (зависимость только
  в `cmd/afterhero` и `internal/render`; `internal/sim` остаётся с нулём
  внешних зависимостей).
- `cmd/afterhero/main.go` — окно 1280×800 (карта 1024 + сайдбар 256),
  заголовок «После героя», `Layout` фиксирует логическое разрешение,
  мир создаётся до окна; `Update`/`Draw` пока пустые каркасы.

Проверка: `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.

### M2.2 — рендер снапшотов плейсхолдерами

- `internal/render/render.go` — `Renderer` (read-only: только
  `SetSnapshot`/`Draw`, изменить мир физически нечем); слои кадра:
  сайдбар → терраин → предметы на полу → живые существа поверх;
  рамка текущего тела игрока; палитра плейсхолдеров — фракции читаются
  цветом (гоблины зелёные, крысы серые, культисты лиловые).
- `sim.World.Terrain()` — статичный терраин один раз в рендер
  (без копии 640 клеток каждый кадр).
- `cmd/afterhero` — связка: Draw берёт `world.Snapshot()` и передаёт
  рендеру.

Проверка: `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.

### M2.3 — FOV, свидетели и туман

- `internal/sim/fov.go` — `KindSight` (гоблин 6, крыса 5, культис 7);
  симметричная `visible` (обе линии Брезенхэма — туда и обратно —
  должны быть чистыми: свидетель видел событие ⟺ участник мог видеть
  свидетеля; лицо стены видно, за стену — нет); `VisibleCells` (построчный
  детерминированный порядок); `witnesses` — живые видящие событие,
  актёр включён всегда.
- `step.go` — события Wait/Moved несут свидетелей, вычисленных при эмиссии.
- `internal/render` — туман: `explored` накапливается в рендере (терраин
  помнит всё, переживёт переселения), `visible` приходит из симуляции;
  существа и предметы вне FOV не рисуются, исследованное вне взгляда темнеет.
- `internal/sim/fov_test.go` — блокировка стенами, радиус, симметрия
  (брутфорс всех пар в радиусе 7 по всей карте), форма FOV, свидетели
  события в кладовой (только гоблины, канонический порядок).

Проверка: `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.

### M2.4 — ввод и сайдбар

- `internal/journal/journal.go` — проекция событий в короткие русские фразы:
  имена «гоблин #1» постоянны (труп того же гоблина — тот же №1),
  направления словами, TurnEnded не печатается. Пакет без графики и без
  права менять мир.
- `internal/render` — сайдбар: шрифт Go Regular (полная кириллица, встроен
  через gofont, не зависит от системных шрифтов), панель «ход / тело /
  здоровье / события / ошибка», подсказка управления.
- `cmd/afterhero` — ввод: стрелки, vi-клавиши (hjkl+yubn), нумпад,
  `.`/Space — ожидание; невалидное намерение → красное сообщение
  на панели, ход не расходуется; буфер последних событий для сайдбара
  (свежие сверху).
- `internal/journal/journal_test.go` — фразы и имена.

Проверка: `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.

**Веха M2 закрыта**: окно, рендер со туманом, свидетели, ввод и сайдбар —
