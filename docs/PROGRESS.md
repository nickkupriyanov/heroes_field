# Журнал разработки «После героя»

Накопительный журнал прогресса. Одна запись на микроэтап: что сделано,
как проверить. Пополняется в том же коммите, что и микроэтап.

## M0 — подготовка

### M0.1 — инициализация проекта

- Установлен Go 1.27.1 (`brew install go`).
- Инициализирован git-репозиторий и модуль `afterhero`.
- `.gitignore` для бинарников и артефактов Go.

Проверка: `go version` → go1.27.1 darwin/arm64.

### M0.2 — спецификация и процесс

- `DESIGN.md` — финальная спецификация MVP с тремя поправками,
  принятыми при ревью: `turn++` — последняя операция `Step`; страх — чистая
  производная от памяти без хранимого поля; выбор тела кодируется событием
  `BodyChosen` (не расходует ход, но воспроизводится в replay).
- `docs/PROGRESS.md` — этот журнал.
- Процесс: микроэтап → зелёные `go test ./...` и `go vet ./...` → запись сюда →
  осмысленный коммит.

## M1 — чистое ядро симуляции

### M1.1 — идентификаторы и стабильные enum'ы

- `internal/sim/id.go` — `EntityID`, `ItemID`, `Seq` (все с 1, ноль = «участника нет»,
  переиспользование ID запрещено), `Vec2` с `Add` и `Manhattan`.
- `internal/sim/enums.go` — все сериализуемые enum'ы с явными стабильными
  значениями: клетки, виды существ (= фракции в MVP), действия, события (15 видов),
  предметы, причины смерти/урона, состояния целей мести, исходы кампании.
  Схема событий: `SchemaVersion = 1`.
- `internal/sim/enums_test.go` — `TestEnumStability` фиксирует каждое числовое
  значение (переупорядочивание констант = громкий провал, а не тихая порча replay);
  `TestVec2` — арифметика координат.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.2 — события и действия

- `internal/sim/event.go` — плоская структура `Event` (один struct на все виды
  фактов: фиксированный порядок полей сериализации бесплатно, лёгкий байт-в-байт
  диф); `Cause` полисемантично по Kind; `EventKind.Memorable()` — договор отбора
  фактов в память: бытовые факты не топят кольцо, метафакты игрока (переселение,
  цели мести) обитателям недоступны.
- `internal/sim/action.go` — `Action` как намерение + конструкторы
  (Move/Wait/Attack/PickUp/Drop/Use) + `Validate()` — синтаксическая валидация
  без мира; `ErrInvalidAction` (без событий, без расхода хода).
- `internal/sim/event_test.go` — round-trip JSON, порядок полей, omitempty,
  таблица Memorable, таблица валидации действий.

Проверка: `go test ./...` и `go vet ./...` — зелёные.

### M1.3 — сценарий: ручная карта 32×20

- `internal/sim/scenario.go` — `defaultMap`: ручная карта с тремя зонами
  (кладовая гоблинов, большой зал, святилище культистов, крысиные тоннели),
  12 существ (4×гоблин, 4×крыса, 4×культис), 6 еды и 2 оружия; строгий
  `ParseMap` (прямоугольность, известные символы, порядок чтения = будущий
  порядок ID); `Cell` вне карты = стена, `Walkable`.
- `internal/sim/scenario_test.go` — размеры, состав населения и предметов,
  уникальность позиций, замкнутость границ, BFS-связность от игрока до
  каждого существа и предмета (герметичная зона = тише гроба), ошибки парсера.

Дизайн-решение: `Scenario` не содержит ID и состояния — их назначает
`NewWorld` в M1.4, так genesis-событие остаётся полным описанием партии.

Проверка: `go test ./...` и `go vet ./...` — зелёные.
